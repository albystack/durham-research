However, there are three blockers before launching new weight distributions.

1. The height observable needs an independent validation
The central-cut implementation is internally consistent with the documented Temperley-flow convention, and I found no obvious indexing or matching defect. But the current test only verifies that the increment lies between −r and r.

There is no independent test that:

constructs the dimer flow separately;

integrates it along an alternative path;

confirms path independence;

exhaustively checks tiny-grid matchings;

validates reflection and sign conventions.

This is the largest mathematical verification gap. The existing result is plausible, but the claim that the integer is the exact dimer height increment needs a stronger test than the implementation checking itself.

2. The pooled BIC is not fully covariance-aware
The pooled bootstrap correctly resamples whole environments jointly across the four fractions. That part is good.

But the pooled regression and BIC calculation subsequently treat the four fraction-level residuals as independent observations. They are correlated because they come from the same two trees in the same environment. Consequently:

pooled coefficient intervals respect environment clustering;

pooled BIC does not use the full cross-fraction covariance;

large pooled BIC values may be overstated.

The analysis should add block-GLS using a bootstrap-estimated 4×4 covariance matrix at each order, together with leave-one-order-out or rolling-origin prediction.

3. The runner cannot safely produce the proposed robustness campaigns
The core already implements:

directed Gamma;

directed lognormal;

undirected conductances.

But the campaign runner currently:

accepts Gamma only;

labels every non-baseline dataset gamma;

prints Gamma parameterisation in all metadata;

does not include the distribution law in its seed identity;

would silently mislabel lognormal and undirected results.

This must be corrected before generating further data.
